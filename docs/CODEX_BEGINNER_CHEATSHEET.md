# Codex Beginner Cheat Sheet

For 35 students, split into 5 groups of 7. If this is your first time using Codex, start here.

## What Is Codex?

Codex is an AI build partner.

It can help you:

- understand files
- write code
- fix errors
- run checks
- improve the design
- prepare a demo and pitch

Your job is to steer. Codex does not know your community like you do.

## Today's Mission

Your group is not trying to build a perfect app.

Your group is trying to build one small demo that shows:

- one real problem
- one clear user
- one useful action
- one simple screen or flow
- no real personal data

## Group Roles

Give everyone a job:

- Driver: types into Codex.
- Problem owner: explains the real problem.
- User owner: says who the app is for.
- Tester: checks if the demo works.
- Designer: checks if it is easy to understand.
- Pitch lead: prepares the 5-minute story.
- Timekeeper: keeps the group moving.

## The First Sentence

Fill this in before coding:

```text
A [specific person] in Soweto struggles with [specific problem], so our app helps them [specific result].
```

Examples:

```text
A clinic visitor in Soweto struggles to know where to find affordable care, so our app helps them compare nearby options and referral contacts.
```

```text
A commuter in Soweto struggles with traffic delays, so our app helps them see reported delays and choose a better route.
```

```text
A family looking for a missing person struggles to share information safely, so our app helps them create a fictional case record and see the next reporting steps.
```

## First Prompt To Paste Into Codex

```text
We are using Codex for the first time.

We are a team of 7 students in the Boundless Soweto AI App Development Challenge.

Our problem is: [write the problem]
Our user is: [write the person]
Our app should help them: [write the result]

Please explain the plan in simple language. Then help us build the smallest demo version of this app. Teach us what you are doing as you go. Use fake data only. Do not use real personal data.
```

## Three Codex Moves

### Plan Mode

Use when you are confused or choosing what to build.

Say:

```text
Use Plan mode. Do not edit yet. Help us choose the first small demo we can finish today.
```

### Goal Mode

Use when you know what you want and need Codex to keep working toward it.

Say:

```text
By the judging time, help us build a working demo for [user] that shows [main action]. Keep it simple and explain each step.
```

### Side Chat

Use when you need Codex to explain something without stopping the main task.

Say:

```text
Side chat: explain what is done, what is broken, and what we should do next.
```

## What Is A Harness?

A harness is a short set of notes that helps Codex understand your project.

For today, your harness can be just this:

```text
User:
Problem:
Main action:
Fake data we can use:
What the demo must show:
How we check it works:
```

Ask Codex:

```text
Create a simple AGENTS.md for our app. It should tell Codex our user, problem, main demo, and the rule: use fake data only.
```

## Build One Flow

Do not try to build everything.

Pick one action:

- Safety: show a fictional safety report and useful contact information.
- Healthcare: find affordable care options and referral contacts.
- Missing people: create a fictional case record and show reporting steps.
- Traffic: report a delay and show a simple route status board.

Important: for safety, healthcare and missing people, this is a prototype. Do not promise emergency response. Do not use real names, real photos, ID numbers, phone numbers or addresses.

## Ask Codex For The Next Step

Use these prompts:

```text
Build the first screen for this demo.
```

```text
Run the app locally and tell us the link to open.
```

```text
The app has an error. Read the error and fix it step by step.
```

```text
Make the screen easier for judges to understand in 30 seconds.
```

```text
Create a 5-minute pitch based only on what our demo actually does.
```

## Green Means Ready Enough

Before judging, check:

- The app opens.
- The main screen is clear.
- One user can complete one action.
- All data is fake.
- The team can explain the problem.
- The team can explain what Codex helped build.
- The team can say what they would build next.

If something is broken, ask:

```text
We have little time. What is the fastest fix so the demo still makes sense?
```

## Remember

You do not need to know everything.

Start with the problem. Tell Codex what you want. Let Codex help you build one useful thing.
