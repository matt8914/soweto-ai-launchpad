# Prompt Library

These prompts help teams use Codex as a build partner during the challenge.

## Understand The Repo

```text
Read this repo and explain harness engineering in plain language for a team of first-time Codex users. Then explain how you can help us build whatever app we choose.
```

## Start Building

```text
We are building for the [challenge track] track.
Our app idea is [app idea].
Our target user is [specific user].
The problem is [specific problem].
The demo must be ready by [time].

Help us build. Teach while building. Use the smallest useful harness and tell us which Codex feature you are using when it matters.
```

## Use Plan Mode

```text
Use Plan mode. Read the current files and do not edit yet.

Turn our idea into a practical build plan. Recommend the simplest stack, the first screen or flow, the smallest useful harness, and the first red/green check.
```

## Create The Goal

```text
Draft a Goal mode objective for this project. It should include our demo outcome, acceptance criteria, checks, and the teaching moments you should point out while building.
```

## Red First

```text
Before implementing the next feature, define one lightweight red/green check. It can be an automated test, a manual smoke check, or a demo-script step that currently fails.
```

## Green Next

```text
Make the smallest useful change that turns the current red check green. Keep the implementation simple enough to demo and explain.
```

## Use Side Chat

```text
Side chat: explain what is happening in plain language. What is done, what is still red, what is risky, and what should we do next?
```

## Use Subagents

```text
Use subagents if they are available and materially useful. Keep the main thread focused on decisions. Suggested split: one subagent checks the demo flow, one reviews the pitch/business case, and the main thread keeps building.
```

## Improve The Design

```text
Review the UI like a product designer. Improve clarity, hierarchy, spacing and the first impression. Do not copy protected designs, logos, paid templates or exact trade dress.
```

## Prepare The Pitch

```text
Use the working demo and acceptance criteria to prepare a five-minute pitch. Keep it honest: say what works, what is mocked, why the problem matters, and what the next pilot step would be.
```
