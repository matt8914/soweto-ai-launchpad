# Simple Group Run Plan

For 35 students, use 5 groups of 7.

The goal is not to teach advanced Codex. The goal is to help each group experience: "I can describe a problem, ask Codex for help, and build a small working demo."

## First 10 Minutes: Reset The Room

Say:

```text
We are going simple now. You do not need to understand all of AI. You only need to choose one real problem, explain it clearly, and ask Codex to help you build one small demo.
```

Then assign roles:

- Driver
- Problem owner
- User owner
- Tester
- Designer
- Pitch lead
- Timekeeper

## Next 10 Minutes: Collect Problems

Ask each group:

```text
What is one problem you or your family have seen in real life?
Who exactly has this problem?
What would help them in one small way?
```

Write problems as:

```text
A [person] struggles with [problem], so our app helps them [result].
```

## Next 15 Minutes: Choose One Safe Demo

For high-risk problems, keep the app as an information, referral, reporting or coordination prototype.

Safety examples:

- fictional safety report board
- safe route information page
- emergency contact explainer

Healthcare examples:

- affordable clinic finder with fake data
- medicine pickup reminder demo
- referral information page

Missing people examples:

- fictional missing-person case tracker
- "what to do next" reporting guide
- anonymous tip flow using fake data

Traffic examples:

- delay report board
- taxi route status page
- commuter notice board

Rule:

```text
No real personal data. No real names, phone numbers, ID numbers, photos, addresses or medical details.
```

## Main Build Prompt

Each group pastes:

```text
We are using Codex for the first time.

We are a team of 7 students in the Boundless Soweto AI App Development Challenge.

Our problem is: [problem]
Our user is: [user]
Our app should help them: [result]

Please explain the plan in simple language. Then help us build the smallest demo version of this app. Teach us what you are doing as you go. Use fake data only. Do not use real personal data.
```

## Checkpoints

Checkpoint 1:

```text
Can the team explain the problem in one sentence?
```

Checkpoint 2:

```text
Has Codex created or changed files?
```

Checkpoint 3:

```text
Can the group open the app or show a screen?
```

Checkpoint 4:

```text
Can one user complete one action?
```

Checkpoint 5:

```text
Can the pitch lead explain the demo in 5 minutes?
```

## If A Group Gets Stuck

Tell them to paste:

```text
We are stuck and we are beginners. Explain the problem simply. Then choose the fastest next step and do it. We need a demo more than we need a perfect app.
```

## Judging Criteria

Keep judging simple:

- Real problem: does the team understand the problem?
- Clear user: do they know who it is for?
- Working demo: does one useful action work?
- Responsible prototype: is all data fake and safe?
- Pitch: can they explain why it matters?
- Learning: can they explain how Codex helped?
